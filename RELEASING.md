# Выпуск обновления

Публичный источник — `gh-pages/versions.json` репозитория nicolenkoe/fragment-logo-editor. Данные о пользовательских изображениях не отправляются.

1. Увеличить `versionCode` и версию в AndroidManifest.xml и `dist/release.js`. В versions.json добавить дату, точное `publishedAt` в UTC, канал stable/testing/experimental, изменения и неизменяемые ссылки `/downloads/<version>/fragment-editor.apk`, `fragment-source.zip`, `update.json`. Указать packageName, minSdk и abis. Сохранять прошлые записи. Последний опубликованный совместимый APK выбирается по publishedAt, а не по статусу stable; только явная настройка stableOnly ограничивает канал.
2. Обновить release-catalog.js из versions.json. Целостность текущего APK хранится во внешнем update.json, а не внутри его собственного содержимого. Остальные функции и интерфейс при выпуске исправления обновлений не менять.
3. Выполнить JS-тесты и `FRAGMENT_ANDROID_TOOLS=/path/to/tools bash tests/native-updates.sh`. Собрать APK тем же приватным ключом через android/build-local.sh. Скрипт использует стандартное D8/L8 core-library desugaring для Android 23+ и неизменённый apksig для проверки подписи. Проверить встроенные файлы, packageName, versionCode и сертификат.
4. После окончательной сборки создать update.json командой `python android/make-update-metadata.py --apk <signed.apk> --tools <tools> --output <release-dir>/update.json`. Скрипт отказывается заменять уже существующие отличающиеся метаданные. SHA-256, размер, пакет, версия, minSdk, ABI и сертификаты извлекаются из настоящего подписанного APK.
5. Скопировать APK и ZIP в текущие downloads и неизменяемый downloads/<version>. Опубликовать все файлы вместе с versions.json; файлы выпущенной версии не перезаписывать. Проверить все ссылки и хеши после публикации.
6. На Android проверить запуск, несколько возвращений из фона, оба режима каналов, отсутствие стабильных, кэш, прерывание сети, «Позже» и системное подтверждение установки. До проверки на устройстве выпуск оставлять тестовым.

«Позже» относится только к предложению установки той же версии. Никаких суточных ограничений на проверку или загрузку нет. Неполные и непроверенные файлы не выдаются установщику. Перед установкой повторяется полная проверка; URI даёт установщику только право чтения готового APK.

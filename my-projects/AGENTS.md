# Каталог «Мои проекты»

При изменениях выбора версий или загрузки прочитай RELEASE_RULES.md. Проверка свежести должна оставаться общей для всех карточек: Android AppBuilds.latest + проверка непосредственно в downloadProject; браузер BuildCatalog.latest + обработчик APK.

Нельзя начинать загрузку из сохранённой или встроенной ссылки без успешной проверки источника. Не возвращать такую ссылку при ошибке сети. Не понижать известный номер версии. Проверяй сценарии 0.64 → 0.67, устаревший ответ, ошибку источника, двойное нажатие и все шесть форматов каталогов.

Тексты описаний веб-карточек находятся в descriptions.js: обе веб-версии используют один файл. В APK длинные описания не добавлять без просьбы пользователя. В публичной витрине не показывать сам каталог, Codex или репозитории.

Не перезаписывать опубликованные APK. Новые выпуски подписывать прежним ключом; перед публикацией проверить номер, подпись, размер и SHA-256. Не публиковать ключ подписи или его пароль. Сохранять старые релизы и не менять их метаданные.

Картинки для пользователя — внешними ссылками, без встроенного просмотра. С APK всегда давать адрес сайта. Проверки на Android-устройстве не объявлять выполненными без устройства.

## Завершение заданий и публикация

Постоянное указание пользователя для этого проекта: каждое выполненное задание с изменениями доводить до сборки и публикации новой версии на GitHub, без отдельного напоминания «жду новую версию». Это относится и к серии поручений: объединить их в законченный выпуск. После публикации сообщить номер и дать APK и адреса сайтов. Не заканчивать выполненные изменения только обещанием собрать позже. Проверки и сохранение прежней подписи обязательны; если публикация реально заблокирована, явно сообщить об этом.

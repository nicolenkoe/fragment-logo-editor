# Правила актуальности APK

Эти правила общие для всех шести карточек в Android и личной веб-версии. Номера в публичной витрине используют тот же механизм выбора.

1. Сохранённый список и встроенные номера нужны для отображения при запуске. Они не разрешают начать скачивание без новой проверки.
2. Каждое нажатие APK запрашивает официальный источник повторно, с уникальным параметром `_hub_check` и отключённым HTTP-кешем. Тестовые и экспериментальные APK учитываются; Windows-файлы не подменяют Android.
3. Версия сравнивается по versionCode; при отсутствии кода — по числовым частям версии. Более старый ответ не заменяет уже известные данные.
4. Только успешная проверка возвращает точный URL, обновляет номер в карточке и передаёт этот URL диспетчеру загрузок. Повторное нажатие во время проверки не запускает второй запрос.
5. Ошибка сети, неизвестный формат, отсутствие APK или ответ старее известной версии блокируют загрузку. Пользователь получает сообщение и может повторить проверку. Молчаливого перехода на старый APK нет.
6. В Android успешная загрузка повторно используется только после свежей проверки, если она всё ещё указывает на тот же URL. Загрузка другой новой версии имеет другой URL и не блокируется старой загрузкой.

## Источники

| Проект | Официальный источник |
| --- | --- |
| CamaraD | `CamaraD-downloads/releases.json`, Android-файл в `android.file` |
| Enduro Club | `enduro-club-downloads/releases.json` |
| Фрагмент | `fragment-logo-editor/release-catalog.js` |
| Хвост под контролем | `hvost-pod-kontrolem-downloads/release.json` |
| Запись экрана | GitHub Releases `screen-recorder-downloads`, последний опубликованный релиз с APK |
| Мои проекты | `fragment-logo-editor/my-projects/releases.json` |

У CamaraD относительные адреса `./downloads/...` относятся к файлам `main/site/downloads` в репозитории распространения, а не к несуществующей папке GitHub Pages. Исправление применяется при каждом разрешении ссылки.

## Правила публикации проектов

- Сначала опубликовать APK под новым неизменяемым URL, проверить номер версии и пакет внутри APK, размер и SHA-256.
- Не заменять содержимое уже опубликованного APK по прежнему URL. Новая сборка должна получать новый номер и URL.
- Затем обновить канонический файл версий, из которого берут данные сайт и каталог. Страница сайта не должна объявлять сборку раньше обновления этого файла.
- versionCode должен возрастать; не смешивать номера Android и Windows. Черновики и отозванные сборки не являются актуальными.
- Проверять после развёртывания, что метаданные, кнопка сайта и фактический APK указывают на одну версию.

## Ограничение

Проверка фиксирует последнюю версию на момент ответа источника. Если следующая сборка опубликована после начала скачивания, она будет получена при следующем нажатии. При недоступном или не обновлённом источнике нельзя достоверно объявить другую сборку актуальной — в этом случае приложение не должно молча скачивать старую.
